Quickstart

Перший запуск після збірки

Дроти припаяні, VTX підключений, антена встановлена. Запиши чистий Raspberry Pi OS Lite, один раз підключись по SSH і запусти install.sh — більше нічого вручну налаштовувати не потрібно.

Результат

Після install.sh пристрій сам запускає веб-панель у твоїй Wi-Fi мережі. SSH більше не потрібен для звичайного користування.

Безпека

VTX не можна вмикати без антени. Не вимикай живлення під час завантаження або конвертації відео.

  1. Запиши Raspberry Pi OS Lite на microSD через Raspberry Pi Imager. В налаштуваннях Imager увімкни SSH і встанови логін/пароль.

    Завантажити Raspberry Pi Imager
    Перед записом

    Переконайся, що обрав правильний носій — всі дані на ньому буде стерто.

  2. Встав microSD в Raspberry Pi, подай живлення і підключись по SSH з ноутбука.

    SSH 
    ssh pi@vtxpi.local

  3. Склонуй репозиторій і перейди в папку проєкту.

    Клонування 
    git clone https://github.com/oleksiiasanov/imitator.git
cd imitator

  4. Запусти скрипт встановлення. Він сам встановить пакети, створить .venv, налаштує composite-вихід, systemd service, GPIO17/MOSFET і перезавантажить пристрій.

    Встановлення 
    chmod +x install.sh && sudo bash install.sh
    Автоматичне перезавантаження

    Після завершення скрипт перезавантажить Raspberry Pi самостійно. SSH-з'єднання обірветься — це нормально.

  5. Зачекай 1–2 хвилини, поки Raspberry Pi завантажиться після перезавантаження.

    Очікуваний результат

    Raspberry Pi підключається до Wi-Fi, який ти задав у Imager, і запускає веб-панель.

  6. На телефоні або ноутбуці підключись до тієї самої Wi-Fi мережі, яку ти задав для Raspberry Pi в Imager.

    Wi-Fi 
    та сама мережа, що в Raspberry Pi Imager
    Нормальна поведінка

    Wi-Fi Access Point ще не реалізований. Якщо потрібна автономна мережа без роутера, це наступний окремий етап.

  7. Відкрий браузер і перейди в панель керування.

    Панель керування 
    http://vtxpi.local:8080
http://<raspberry-pi-ip>:8080
    Фінальний результат

    Відкривається сторінка VTX Video Control. Далі відео, scheduler і playback керуються з браузера.

Як працює автозапуск

  • Raspberry Pi увімкнеться і завантажить систему.
  • Веб-інтерфейс запуститься автоматично.
  • Пристрій почекає задану кількість хвилин до першого запуску.
  • Запустить відео, дочекається завершення і повторить запуск після заданого інтервалу.

Замінити відео пізніше

  • Увімкни пристрій.
  • Підключись до тієї самої Wi-Fi мережі, де Raspberry Pi.
  • Відкрий http://vtxpi.local:8080 або http://<raspberry-pi-ip>:8080.
  • Завантаж нове відео і дочекайся конвертації.
  • Старе відео автоматично заміниться новим.

Сторінка не відкривається

  • Перевір, чи пристрій увімкнений.
  • Перевір, чи пройшло 1-2 хвилини після подачі живлення.
  • Переконайся, що телефон або ноутбук у тій самій Wi-Fi мережі, що Raspberry Pi.
  • Перевір адресу: http://vtxpi.local:8080 або IP Raspberry Pi.
  • Онови сторінку або перезапусти живлення після паузи 10 секунд.

Відео не видно на приймачі

  • Перевір антену VTX, живлення VTX і частоту приймача.
  • Перевір, чи відео точно завантажилось через веб-інтерфейс.
  • Подивись, чи інтерфейс показує наявність файлу.
  • Натисни Пуск / Пауза для ручного запуску.
  • Якщо видно login Raspberry Pi, VTX і відеовихід працюють, проблема в запуску або файлі відео.

Що не можна робити

  • Не вмикати VTX без антени.
  • Не вимикати живлення під час завантаження відео.
  • Не вимикати живлення під час конвертації відео.
  • Не подавати 6S напряму на Raspberry Pi.
  • Не змінювати дроти, якщо система вже працює.

Швидкі значення

  • Wi-Fi: мережа, задана в Raspberry Pi Imager.
  • Панель: http://vtxpi.local:8080 або http://<raspberry-pi-ip>:8080.
  • Сторінка має назву VTX Video Control.

Фаза 1

Зібрати залізо і правильно підключити VTX

На цьому етапі важливо зробити спільну землю, не переплутати TV pad і не вмикати VTX без антени.

Що потрібно
  • Raspberry Pi Zero 2 W, microSD, Wi-Fi 2.4GHz.
  • Analog 5.8GHz VTX, антена, FPV/SDR receiver.
  • Logic-level MOSFET module для VTX/fan power branch.
  • Дроти, паяльник, USB-C 5V для Pi.
  • Buck converter 6S до 5.1V для майбутнього живлення від акумулятора.
Критично

Перед увімкненням VTX підключи антену. Не вмикай VTX без антени.

  1. Pi TV pad припаяй до VTX VIDEO IN / yellow wire.

  2. Pi GND припаяй до VTX GND / black wire.

  3. Pi GPIO17 підключи до MOSFET control input.

  4. Battery + підключи до MOSFET input, а MOSFET output — до VTX/fan power branch.

  5. Перевір правило: Battery GND = MOSFET GND = VTX GND = Raspberry Pi GND.

    Мінімальна схема підключення 
    Pi TV  -> VTX VIDEO IN
Pi GND -> VTX GND
Pi GPIO17 -> MOSFET control input
Battery + -> MOSFET input
MOSFET output -> VTX/fan power branch
Battery - -> VTX/MOSFET/Pi GND
Результат фази

VTX отримує живлення через MOSFET branch, антена підключена, VIDEO IN бере сигнал з TV pad, GPIO17 керує MOSFET, а всі землі об'єднані.

Фаза 2

Записати Raspberry Pi OS і зайти по SSH

Найпростіший шлях для початківця: одразу задати Wi-Fi, hostname, користувача і SSH в Raspberry Pi Imager.

Завантажити Imager
В Imager вибери

Raspberry Pi OS Lite 64-bit. Якщо Lite не видно, можна Raspberry Pi OS 64-bit.

Wi-Fi

SSID має бути саме тієї мережі, до якої підключений ноутбук. Country: UA, Enable SSH: yes.

  1. У Raspberry Pi Imager задай Hostname: vtxpi, Username: pi, пароль, Wi-Fi SSID і Wi-Fi Password.

  2. Встав microSD у Raspberry Pi.

  3. Живи Pi через USB-C 5V. Не підключай одразу складне живлення через DC-DC.

  4. Почекай 2-5 хвилин після першого boot.

  5. Підключись по SSH з Mac або Linux.

    Основне SSH-підключення 
    ssh pi@vtxpi.local

  6. Якщо macOS/Linux свариться на старий SSH-ключ, видали старий запис і підключись знову.

    Оновити SSH-ключ для vtxpi.local 
    ssh-keygen -R vtxpi.local
ssh pi@vtxpi.local

  7. Якщо .local не працює, знайди IP Raspberry Pi і підключись по IP.

    Підключення по IP 
    arp -a
ssh pi@192.168.X.X
Результат фази

Ти бачиш shell Raspberry Pi через SSH. Якщо Wi-Fi змінився після першого старту, SD не треба переписувати: можна оновити Wi-Fi через bootfs recovery зі вставленої microSD.

Фаза 3

Запустити install.sh і перевірити перший boot

Composite, Python .venv, залежності, systemd service, runtime folders і GPIO self-check налаштовує install.sh. Вручну системні файли не редагуються.

  1. Склонуй репозиторій на Raspberry Pi і перейди в папку проєкту.

    Код проєкту 
    git clone https://github.com/oleksiiasanov/imitator.git
cd imitator

  2. Запусти інсталятор. Його можна запускати повторно: він оновить залежності, service і перевірки без ручних кроків.

    Що робить install.sh

    Після reboot 
    http://vtxpi.local:8080

    Service і journal

journalctl -u vtx-player.service -n 80 --no-pager
Результат фази

Веб-панель відкривається в браузері, service активний, а стартова діагностика показує статус FFmpeg, MPV, Composite-1, GPIO17, uploads, videos і config.json.

Фаза 4

Завантажити відео через Web UI

Відео більше не заливається через scp і не конвертується вручну. Web UI приймає файл, показує upload progress, конвертує через FFmpeg і запускає MPV.

  1. Відкрий головну сторінку VTX Video Control у браузері.

  2. У блоці 1. Завантаження відео вибери файл MP4/MOV/MKV/WEBM/AVI/MPEG/TS і натисни Завантажити нове відео.

  3. Дочекайся upload progress і conversion progress. Під час конвертації кнопка playback заблокована.

  4. Після успішної конвертації app створює videos/video_fpv.mp4, вмикає GPIO17/MOSFET, чекає 300 мс і стартує MPV на Composite-1.

  5. Для ручного запуску або зупинки використовуй кнопку Пуск / Пауза. При stop app зупиняє MPV і вимикає MOSFET.

  6. Якщо upload або conversion падає, повідомлення видно в Web UI, а деталі є в journal.

Результат фази

FPV receiver показує конвертоване відео, GPIO17 керує MOSFET power branch, а Web UI показує зрозумілий статус.

Фаза 6

Перейти на акумуляторне живлення

Коли вся система працює від USB-C і MOSFET branch перевірений, можна переходити на 6S через правильний buck converter для Raspberry Pi.

Для тестів

Pi живити від USB-C 5V, VTX/fan branch живити через MOSFET. Це найспокійніший режим для першого налаштування.

Для 6S

Raspberry Pi не можна живити напряму від 6S. Потрібен step-down / buck converter на 5.1V.

  1. Якщо VTX підтримує VBAT / 6S, живи його через MOSFET branch, а не напряму від Raspberry Pi.

    Живлення VTX через MOSFET 
    6S battery + -> MOSFET input
MOSFET output -> VTX/fan power branch
6S battery - -> VTX/MOSFET/Pi GND

  2. Raspberry Pi живи тільки через step-down / buck converter на 5.1V.

    Живлення Raspberry Pi через buck converter 
    6S battery -> buck converter -> 5.1V -> Raspberry Pi
Перед підключенням Pi

Обов'язково перевір мультиметром 5.1V на виході converter. Не використовуй step-up converter для 6S до Pi.

6S1P

Li-Ion 3500 mAh приблизно 75 Wh. При споживанні 5W це орієнтовно 12-15 годин.

6S2P

Li-Ion 3500 mAh cells приблизно 150 Wh. При споживанні 5W це орієнтовно 24-30 годин.

Результат фази

Система працює автономно, GPIO17 керує MOSFET branch, VTX не перегрівається, Pi отримує стабільні 5.1V, акумулятор має BMS або контроль розряду.

Фінальна перевірка

Чекліст перед автономною роботою

Позначай пункти по мірі виконання. Прогрес зберігається в цьому браузері.

FAQ: змінити Wi-Fi без перезапису SD

Використовуй це, якщо змінився роутер, SSID або пароль, і Raspberry Pi більше не з'являється в мережі. Не натискай Write в Raspberry Pi Imager: це перезапише всю SD-карту.

  • Встав microSD у Mac.
  • Переконайся, що boot-розділ відкрився як /Volumes/bootfs.
  • Заміни YOUR_WIFI_NAME і YOUR_WIFI_PASSWORD на реальні дані Wi-Fi.
  • Raspberry Pi Zero 2 W підключається тільки до 2.4GHz Wi-Fi.
Перевірити bootfs 
ls -la /Volumes/bootfs
cat /Volumes/bootfs/network-config
cat /Volumes/bootfs/cmdline.txt
Створити fixwifi.sh 
cat > /Volumes/bootfs/fixwifi.sh <<'EOF'
#!/bin/bash
set -ex

BOOT_DIR="/boot/firmware"
[ -d "$BOOT_DIR" ] || BOOT_DIR="/boot"
exec > "$BOOT_DIR/fixwifi.log" 2>&1

date
echo "Writing Wi-Fi recovery profile"

mkdir -p /etc/NetworkManager/system-connections

cat > /etc/NetworkManager/system-connections/vtx-wifi.nmconnection <<'WIFI'
[connection]
id=vtx-wifi
type=wifi
interface-name=wlan0
autoconnect=true

[wifi]
mode=infrastructure
ssid=YOUR_WIFI_NAME

[wifi-security]
key-mgmt=wpa-psk
psk=YOUR_WIFI_PASSWORD

[ipv4]
method=auto

[ipv6]
method=auto
WIFI

chmod 600 /etc/NetworkManager/system-connections/vtx-wifi.nmconnection
chown root:root /etc/NetworkManager/system-connections/vtx-wifi.nmconnection

nmcli connection reload || true

sed -i 's| systemd.run=/boot/firmware/fixwifi.sh systemd.run_success_action=reboot||' "$BOOT_DIR/cmdline.txt"
rm -f "$BOOT_DIR/fixwifi.sh"
sync
EOF

chmod +x /Volumes/bootfs/fixwifi.sh
Додати одноразовий запуск 
python3 - <<'PY'
from pathlib import Path
path = Path("/Volumes/bootfs/cmdline.txt")
token = "systemd.run=/boot/firmware/fixwifi.sh systemd.run_success_action=reboot"
line = path.read_text().strip()
if token not in line:
    path.write_text(line + " " + token + "\n")
PY
Перевірити перед вставленням у Pi 
grep -n "YOUR_WIFI\|systemd.run\|ssid=\|psk=" /Volumes/bootfs/cmdline.txt /Volumes/bootfs/fixwifi.sh /Volumes/bootfs/network-config
diskutil eject /Volumes/bootfs
  • Після цього встав SD у Raspberry Pi і подай живлення.
  • Почекай 2-3 хвилини: Pi має виконати fixwifi.sh, перезавантажитись і підключитись до нового Wi-Fi.
  • Після другого boot пробуй ping vtxpi.local, ssh pi@vtxpi.local або відкрий http://vtxpi.local:8080.
Якщо знову не підключилось 
ls -la /Volumes/bootfs/fixwifi.sh
cat /Volumes/bootfs/fixwifi.log
grep systemd.run /Volumes/bootfs/cmdline.txt
grep -n "ssid=\|psk=" /Volumes/bootfs/fixwifi.sh /Volumes/bootfs/network-config
  • Якщо fixwifi.sh зник і systemd.run зник з cmdline.txt, скрипт виконався. Тоді перевір SSID, пароль, 2.4GHz Wi-Fi і список клієнтів роутера.
  • Якщо fixwifi.sh лишився і systemd.run лишився, скрипт не стартував. Перевір, що cmdline.txt є одним рядком і що SD була коректно eject-нута.
  • Якщо fixwifi.log є, відкрий його: там буде видно, на якому кроці зупинився recovery.

Немає відеосигналу

  • Перевір у /system, чи MPV, FFmpeg, Composite-1 і GPIO17 мають зелений статус.
  • Перевір, чи MOSFET branch вмикає VTX під час playback.
  • Перевір, чи антена підключена до VTX.
  • Перевір, чи VTX не в PIT mode.
  • Перевір band/channel на receiver.
  • Перевір, чи VIDEO IN припаяний саме до Pi TV pad.

SSH не підключається

  • Почекай 2-5 хвилин після першого boot.
  • Переконайся, що ноутбук і Raspberry Pi в одній Wi-Fi мережі.
  • Спробуй ssh-keygen -R vtxpi.local.
  • Знайди IP через arp -a або сторінку роутера.
  • Якщо Wi-Fi міняли після першого старту, виконай FAQ: змінити Wi-Fi без перезапису SD.

Composite-1 не connected

  • Запусти sudo bash install.sh повторно з папки проєкту.
  • Installer має виставити dtoverlay=vc4-kms-v3d,composite=1.
  • Installer має виставити enable_tvout=1 і sdtv_mode=2.
  • Installer має додати video=Composite-1:720x576@50e.
  • Після зміни boot config потрібен reboot.

Upload або conversion падає

  • Перевір, чи тип файлу підтримується: MP4, MOV, MKV, WEBM, AVI, MPEG, TS.
  • Перевір вільне місце на /system.
  • Перевір, чи ffmpeg доступний на /system.
  • Подивись помилку в Web UI і journalctl -u vtx-player.service -f.
  • Під час conversion playback заблокований — це нормально.
